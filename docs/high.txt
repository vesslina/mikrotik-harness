5.## Connection: a dedicated SSH channel
- Хорошо подумать над реализацией именно этого, самая важная часть работы.

MikroMCP's own `run_command` is a single guarded call with a static deny-list — not suited to an
open-ended, stateful CLI session, and it stays outside model RBAC per the existing design. HIGH
RISK mode needs its own connection, separate from MikroMCP's REST path:
- **asyncssh**, one persistent PTY for the whole HIGH RISK session — not a new connection per
  command. RouterOS Safe Mode and the current CLI menu context only live inside one continuous
  session.
  
- **SSH host-key pinning** for this specific channel, independent of the TLS fingerprint already
  pinned for MikroMCP's REST path (a different protocol, a different trust record). Reuse the
  same trust-on-first-use pattern already implemented for TLS: show the fingerprint, require
  confirmation on first use, hard-stop on a later mismatch. Store it alongside the router's
  existing `.mth/mikromcp/` entry.
  
- **Command framing**: after each command, send a service marker
  (`:put "CMD_DONE_<uuid>"`) and read the stream until it appears, then strip it. Handle
  separately: local echo may contain the marker before the real result; RouterOS may emit
  asynchronous messages outside a command's response; a command may hang (needs a timeout);
  the connection may drop mid-session.
- Executor request/response shape: request (`command`, `timeout`, `max_output_bytes`); response
  (`raw_output`, `cleaned_output`, `status`, `session_alive`, `safe_mode_active`,
  `execution_time`).
  
## Safe Mode

Enter Safe Mode automatically the moment the SSH session opens, and confirm it programmatically
(the `<SAFE>` prompt marker), not by assumption. This is a pure safety gain with no cost to the
model's freedom of action — it does not restrict which commands can run, only adds an automatic
rollback if the connection drops before the session ends cleanly. Two real limits to design
around rather than ignore:
- `Ctrl+D` rolls changes back; **a plain `/quit` does not** — it is a normal termination and
  changes remain in effect. The harness must never send `/quit` to close the channel while the
  session state is unresolved; closing HIGH RISK cleanly means an explicit choice between
  "commit and exit" and "abort and roll back."
  
- Safe Mode's history holds roughly the last 100 actions; on overflow it silently exits Safe Mode
  with no automatic rollback of what remains. Track the command count for the session and warn
  the operator (in the status line, not blocking) as it approaches that limit, so a manual
  checkpoint can be taken deliberately instead of losing the safety net unnoticed.
  
  
6.## Tool surface inside HIGH RISK

- Every read tool and `propose_typed_*` tool already available in `READY`.
- The new `ssh_exec(command)` tool: sends one line to the persistent session, returns the framed
  response. No per-call confirmation gate — that friction is what this mode deliberately removes.
